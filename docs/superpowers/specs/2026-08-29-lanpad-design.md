# lanpad — дизайн

**Дата:** 2026-08-29
**Статус:** согласован, готов к планированию
**Лицензия проекта:** GPL-3.0

## Что это

Телефон становится тачпадом, клавиатурой и пультом управления медиа для компьютера
в той же локальной сети. Агент на компьютере раздаёт веб-приложение и внедряет ввод
в систему. Телефон подключается по локальному адресу, приложение добавляется на
домашний экран и открывается без браузерной обвязки.

Проект вырастает из личного прототипа `remote-touchpad` и выкладывается в открытый
доступ. Причина: существующие приложения в сторах перегружены рекламой, зависят от
чужих серверов и часто не работают.

## Цели

- Управление курсором, кликами, прокруткой, клавиатурой
- Медиа: плей/пауза, вперёд, назад, громкость, текущий трек с обложкой, перемотка
- Установка на домашний экран, запуск без адресной строки
- Работа без интернета, без облака, без учётных записей
- Минимальная задержка отклика курсора
- Проект, который форкается и работает без участия автора

## Не цели

- Работа вне локальной сети (мобильный интернет, другая сеть)
- Трансляция экрана
- Офлайн-работа приложения при выключенном компьютере — управлять всё равно нечем
- Windows и macOS в первой версии (архитектура готовится, реализации нет)
- Магазины приложений

## Ключевые архитектурные решения

### Приложение раздаёт компьютер, а не сайт

Рассматривался вариант с приложением на домене и подключением к компьютеру по
локальному адресу. **Он невозможен технически:** страница, загруженная по `https`,
не может открыть `ws://` или `http://` — правило mixed content блокирует это без
возможности обойти из кода.

Обходной путь существует — настоящий сертификат на локальный IP, для чего нужен
DNS-сервер, разбирающий адрес из имени, wildcard-сертификат и сервис раздачи его
агентам. Отвергнут: он делает каждого пользователя зависимым от домена и
инфраструктуры автора, а приватный ключ wildcard-сертификата пришлось бы
опубликовать в составе агента. Это ровно та болезнь, из-за которой проект и
затевался.

**Решение:** агент раздаёт приложение по `http` в локальной сети. Ноль
инфраструктуры, ноль внешних зависимостей, полная работоспособность без интернета.

### Service Worker не используется

Установка на домашний экран в standalone-режиме обеспечивается манифестом
(`display: standalone`) и работает по `http` — проверено на живом устройстве.
Service Worker требует secure context и по `http` не регистрируется; в текущем
прототипе его регистрация молча падает в пустой `catch`.

Офлайн-кэш здесь не нужен по существу: приложение раздаёт сам компьютер, и если он
выключен, кэшированное приложение всё равно бесполезно. Быстрый повторный запуск
обеспечивается заголовками кэширования статики. `sw.js` удаляется.

### Спаривание через QR

Агент при запуске показывает QR с адресом вида `http://192.168.1.50:8477/?t=<токен>`.
Телефон сканирует, открывает, добавляет на домашний экран.

**Известное ограничение:** установленный ярлык привязан к адресу. Смена IP по DHCP
ломает его, требуется пересканировать QR. Обходится закреплением адреса на
роутере — описывается в README. Возможное улучшение (`lanpad.local` через mDNS)
вынесено в открытые вопросы.

### Слой платформы

Четыре независимых интерфейса. Каждая реализация объявляет свои возможности; агент
передаёт их приложению, и интерфейс скрывает то, что недоступно. Отсутствие
`MediaBackend` не ломает работу курсора.

| Интерфейс | Обязанность | Реализация для Linux |
|---|---|---|
| `InputBackend` | курсор, кнопки, клавиши, набор текста | `uinput` через `evdev` |
| `AudioBackend` | громкость, отключение звука | `wpctl` (PipeWire) |
| `MediaBackend` | плей/пауза, треки, метаданные, перемотка | MPRIS через D-Bus |
| `ClipboardBackend` | вставка текста, включая кириллицу | `wl-copy` |

Порт под другую систему — новый каталог в `platform/`. Приложение и протокол не
меняются.

### Протокол

Двусторонний обмен по одному WebSocket-соединению.

**Телефон → агент.** Пакет событий, накопленный за кадр. Формат сохраняется из
прототипа: `[["m",dx,dy],["click","l"],["volset",62]]`. Добавляется `["seek",<сек>]`.
Валидация переносится в `protocol.py` — сейчас разбор размазан по обработчику.

**Агент → телефон.** Состояние, отправляемое по изменению, а не по запросу:

```json
{
  "type": "state",
  "audio": { "volume": 62, "muted": false },
  "media": {
    "playing": true,
    "title": "Bohemian Rhapsody",
    "artist": "Queen",
    "art": "https://…  |  /art?id=…",
    "position": 134.2,
    "duration": 355.0,
    "canSeek": true
  },
  "caps": { "media": true, "audio": true, "clipboard": true }
}
```

Источник обновлений — сигналы `PropertiesChanged` из D-Bus, не опрос. Позиция трека
отправляется редко, между обновлениями телефон досчитывает её сам, исходя из
состояния воспроизведения. Опрос `/vol` каждые четыре секунды, существующий в
прототипе, удаляется.

Запасной путь через `POST /e` сохраняется: он спасает, когда WebSocket разорван.

**Обложка.** MPRIS отдаёт `mpris:artUrl`. Внешние ссылки (`https`) передаются как
есть, телефон грузит их сам. Локальные файлы (`file://`) отдаёт агент через
`/art?id=…`, где идентификатор указывает на путь из текущих метаданных —
произвольные пути не принимаются.

**Перемотка.** Не все плееры её поддерживают; MPRIS сообщает об этом флагом
`CanSeek`. Флаг передаётся телефону, и полоса становится индикатором без
возможности тянуть, а не обманывает пользователя.

## Приложение

Стек: Vite + React + TypeScript. Сборка в CI, готовый `dist` входит в пакет —
установка агента не требует Node.

### Экран

Одна прокручиваемая колонка, без вкладок и маршрутизации:

1. Строка состояния — связь, имя компьютера, настройки
2. Медиа-карточка — обложка, название, исполнитель, фейдер позиции, три кнопки
3. Тачпад — основная площадь
4. Ряд кликов — левый, правый, средний
5. Фейдер громкости с отключением звука
6. Быстрые клавиши и вызов клавиатуры

Медиа-карточка не рендерится, когда ничего не играет — не остаётся пустого места.

### Тачпад: полоса прокрутки у правого края

Вдоль правого края тачпада идёт узкая полоса. Ведение по ней **одним пальцем**
прокручивает страницу — так же, как это делали тачпады ноутбуков до эпохи
жестов. Прокрутка двумя пальцами по всей площади остаётся: полоса нужна для
случая, когда телефон держат одной рукой и второй палец занять нечем.

Правила, без которых это работать не будет:

- **Касание принадлежит тому, где началось.** Палец, начавший движение в
  полосе, до отрыва управляет прокруткой, даже если уехал влево. Иначе
  прокрутка будет срываться в движение курсора на каждом косом движении
- **Касание в полосе не даёт клика.** Иначе неудачный хват страницы обернётся
  нажатием в случайном месте
- **Полоса видна.** Невидимая функция, о которой знает только автор, для
  опенсорса бесполезна: край помечается ненавязчиво, а при касании
  подсвечивается
- Ширина — около десятой части площади, но не уже 28 px: попасть большим
  пальцем вслепую
- Шаги накапливаются тем же способом, что и прокрутка двумя пальцами, и
  отправляются теми же событиями `["w", n]`. На стороне агента менять нечего
- Направление подчиняется настройке «естественная прокрутка», как и жест
  двумя пальцами

### Фейдер

Один компонент для громкости и позиции. Наивная реализация ломается предсказуемо:
палец тянет ручку, прилетевшее состояние дёргает её обратно. Поэтому:

- Пока палец на экране, значение подчиняется только пальцу; входящие обновления
  запоминаются, но не применяются
- После отпускания входящее состояние игнорируется ещё около 400 мс, чтобы не
  поймать пакет, отправленный до нашего изменения
- Отправка не чаще одного раза в ~60 мс, плюс обязательный финальный пакет по
  отпусканию — иначе теряется конечное положение
- Зона захвата 44 px при визуально тонкой полосе
- Касание полосы перемещает ручку в точку, а не только перетаскивание
- Отклик вибрацией через `navigator.vibrate`, отключаемый в настройках

### Клавиатура

Механика переносится из прототипа без изменений: скрытое поле ввода с перехватом
`beforeinput`. Выглядит странно, но это единственный надёжный способ на iOS, и он
уже отлажен. Переписывается на TypeScript.

### Онбординг

Открытие без токена показывает экран «отсканируйте QR на компьютере», а не молча
неработающий тачпад.

### Настройки

Чувствительность, естественная прокрутка, вибро-отклик, насыщенность оформления.

### Язык интерфейса

Приложение и вывод агента — на русском и английском.

**README — на английском, немецком и русском.** Английский канонический и
лежит в `README.md`, переводы рядом: `README.de.md`, `README.ru.md`, ссылки
друг на друга первой строкой каждого.

Переводы расходятся с оригиналом при первой же правке, которую забыли
продублировать, поэтому держим их короткими: подробности живут в английском,
в переводах — назначение, установка, ограничения и ссылка на полный текст.
Расхождение в мелочах лучше, чем перевод, уверенно описывающий то, чего уже
нет.

Языки интерфейса и языки README — разные множества, и это нормально: словарь
приложения устроен так, что добавить немецкий будет стоить одного файла, если
понадобится.

Язык определяется автоматически по языку телефона (`navigator.languages`), с
переключателем в настройках и запоминанием выбора. Незнакомый язык означает
английский. Агент в терминале выбирает язык по локали системы тем же правилом.

Строки живут в одном словаре на язык, а не разбросаны по компонентам:
переводчику должно хватать одного файла. Ключи именуются по смыслу, а не по
тексту, иначе правка формулировки ломает перевод.

Отдельно про длину: русские строки в среднем на треть длиннее английских, и
подписи кнопок обязаны выдерживать это без переноса и обрезки. Проверяется на
самом узком экране из поддерживаемых.

### Язык исходного кода

Код, докстринги, комментарии и сообщения коммитов — **на английском**. Это
норма открытых проектов и единственный способ пустить в проект людей со
стороны: русские комментарии отсекают большинство возможных участников.

Существующий код агента написан по-русски и переводится отдельной задачей
перед публикацией. Перевод не меняет поведение, поэтому проверяется тем, что
набор тестов остаётся зелёным, а в диффе нет изменений кроме текста.

## Оформление

Чёрная основа, плоские панели, акцентный цвет извлекается из обложки текущего трека.

Три степени насыщенности, переключаются в настройках:

| Режим | Что окрашено |
|---|---|
| Спокойный | фейдеры и главная кнопка |
| **Обычный** (по умолчанию) | плюс статичное свечение вверху экрана |
| Насыщенный | плюс подцветка панелей, фейдер градиентом |

Цвет вычисляет телефон: обложка уменьшается до нескольких пикселей на скрытом
canvas, берётся доминирующий оттенок. Насыщенность и светлота поднимаются до
читаемого минимума — иначе тёмная обложка даёт заливку, неразличимую на чёрном.
Контраст текста от обложки не зависит и проверяется отдельно.

## Обязательство по задержке

Оформление легко утягивает отклик вниз, поэтому правила фиксируются явно, а не
остаются на усмотрение реализации.

- **`backdrop-filter` не используется нигде.** Цвет даётся заливкой. Визуальный
  результат близок, стоимость несопоставима
- **Свечение — статичный слой** на собственной композиторной плоскости.
  Перерисовывается только при смене трека
- **Движение пальца не вызывает перерисовку React.** Координаты пишутся напрямую в
  DOM, отправка батчится по `requestAnimationFrame` — механика прототипа верна и
  сохраняется
- **Свечение под пальцем живёт внутри тачпада** и не попадает под другие слои
- Обработчики касаний с `passive: false`, жесты масштабирования подавляются

## Безопасность

Исправляется при переносе, поскольку код становится публичным:

- Токен сравнивается через `secrets.compare_digest` вместо `==`
- Соединения принимаются только из приватных подсетей
- Проверяется заголовок `Origin` при рукопожатии WebSocket
- Отдача обложек ограничена путями из текущих метаданных
- Файл токена исключается из репозитория

Токен передаётся в строке запроса и попадает в историю браузера — иначе спаривание
по QR невозможно. Для локальной сети это приемлемо и **описывается в README прямо**,
а не замалчивается. Любой, кто в той же сети и знает токен, получает полный контроль
над вводом.

## Тестирование

Тестов сейчас нет. Появляются:

**Python (pytest).** Валидация и разбор протокола, фрейминг WebSocket, раскладка
клавиш, логика состояния сессии. Внедрение ввода проверяется через подставной
`InputBackend`; настоящий `uinput` в тестах не используется.

**TypeScript (vitest).** Математика фейдера, включая блокировку входящих обновлений
во время перетаскивания. Интерполяция позиции трека. Извлечение и коррекция цвета
обложки. DOM не тестируется.

## Упаковка и публикация

- Репозиторий `lanpad` на GitHub, GPL-3.0
- Установка: `pipx install lanpad`, затем `lanpad --install-service` — команда сама
  ставит systemd-юнит и показывает QR
- **Требования сборки называются явно.** `evdev` собирает C-расширение, поэтому
  на чистой Fedora нужны `python3-devel` и `gcc`; без них установка падает
  стектрейсом компилятора, в котором про недостающий пакет не сказано ни слова.
  Это первое, обо что споткнётся человек со стороны, поэтому требования стоят
  в README рядом с командой установки, а не в разделе решения проблем
- CI на GitHub Actions: ruff, pytest, vitest, сборка фронта, публикация релиза
- README: демонстрация в виде анимации, установка одной командой, честный раздел
  ограничений — только локальная сеть, только Linux, привязка к IP, модель
  безопасности

### Смена адреса в сети

QR печатается один раз при запуске службы. Стоит смениться сети — переезд с
домашнего Wi-Fi на режим модема, перезагрузка роутера, новый адрес по DHCP — и
код в журнале ведёт в никуда. Человек сканирует, ничего не происходит, и
причину установить нечем: агент при этом бодро рапортует, что работает.

Проверено на живом использовании: адрес сменился с `192.168.178.110` на
`172.20.10.5`, QR остался прежним, спаривание молча перестало работать.

Требования:

- Агент следит за адресом и при смене печатает новый QR в журнал, а не молчит
- README отдельным пунктом объясняет, что делать при смене сети: `lanpad --qr`
  выдаёт свежий код, не мешая работающей службе
- Сообщение о новом адресе называет старый и новый, чтобы связь причины со
  следствием была видна из журнала

### История проекта в README

Раздел «зачем это существует» пишется от автора и своими словами, без
маркетингового тона. Содержание:

MacBook 2015 с установленной Fedora, крышка закрыта, картинка выведена на
27-дюймовый монитор Apple. В такой конфигурации ноутбук стоит где стоит, а
клавиатура и трекпад у него закрыты крышкой — управлять машиной физически

## Открытые вопросы

**mDNS.** Адрес `http://lanpad.local:8477` через Avahi дал бы устойчивое имя вместо
IP и снял бы проблему смены адреса полностью. Chrome на Android, предположительно,
не разрешает `.local`. Проверяется экспериментом; при успехе становится основным
адресом в QR, при неудаче остаётся закрепление адреса на роутере.

**Насыщенность оформления по умолчанию.** Выбран средний режим по мокапу. Уточняется
на живом устройстве, стоимость смены — несколько CSS-переменных.
